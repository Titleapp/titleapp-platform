## 1. Platform-level checklist (run once, not per-worker)

- [ ] **Fresh signup → checkout → real Stripe state.** New account, confirm the default worker bundle lands correctly, start a trial, convert to paid, cancel, refund. Confirm each step writes correct real billing state, not just a clean click-through.
- [x] **Webhook fail-closed** — a deliberately invalid/missing signature is rejected (verified 2026-09-24, live).
- [ ] **Webhook idempotency, real test** — the *code* was fixed and reasoned through (an event-id claim written before any side effect, cleared again on a genuine processing failure so a legitimate retry still works), but not yet exercised with a real Stripe-dashboard "resend webhook." Do that once before trusting it fully.
- [ ] **Cross-tenant isolation spot-check** — the CODEX S52.65 bug class (chat session bleed across tenants). Use a real multi-tenant account (Sean or Kent, both hold memberships in more than one tenant) and confirm nothing crosses.
- [ ] **Seat add/remove** — real-time sync (built this session) plus the quarterly reconciliation job, on an account with actual multiple seats.
- [x] **Back-of-house roster consistency across every real + demo tenant** — real audit run 2026-09-24 (`collectionGroup("workspaces")` against the current 6-worker back-of-house set). Findings: 7 workspaces correctly have none (confirmed member/client-role portals — by design, not a bug); 10 admin/operator workspaces were missing `investor-relations` and/or `platform-legal` — fixed at the root for 6 of them (same class of fix as the demo-persona reset bug); 2 backfilled directly (real, non-demo-reset tenants); **1 residual risk flagged, not fully closed**: the `realestate`/Merritt Capital Group demo tenant has some other, unidentified write path merging into its `activeWorkers` array beyond the `PERSONAS` map — patched directly but the actual mechanism is still untraced. Worth tracing before relying on that specific demo.
- [x] **The multi-tool-call fix** (found via Reed, "who do I call today" silently failing) — spot-checked as part of finding/fixing it; worth 2–3 more spot-checks on other workers before 1.0 since it was a shared code path (26 call sites), not Reed-specific.

## 2. Per-worker checklist (repeat for every worker)

Priority order: real customer-facing workers first (Petra/title — Attorney's Title, Hannah/nursing — UH Maui, Skye/aviation — Sean's own use), then the six back-of-house workers (every tenant gets these), then the long tail of less-used vertical workers as best-effort.

For each worker:
- [ ] **Identity check** — right persona name everywhere it appears (chat header, sidebar, cross-worker routing), no leaks like "Platform Legal · Worker" instead of "Sterling."
- [ ] **Data tools against an EMPTY tenant** — graceful "no data yet," not a crash or a hallucinated answer. (This exact bug hit Reed on 2026-09-24 — the fix was structural, but re-verify per-worker since each has its own tools/data shape.)
- [ ] **Data tools against REAL, populated data** — correct real answer, source-grounded, not fabricated.
- [ ] **A compound/ambiguous question** likely to trigger two tool calls in one turn — confirms no regression of the multi-tool-call bug.
- [ ] **Canvas renders a real card**, not blank, for at least one real interaction.
- [ ] **Cross-worker routing** — a question that belongs to a different worker correctly hands off; an in-scope question doesn't.
- [ ] **Claude-in-Chrome stress test** (per the updated `CREATOR-SETUP.md` Step 11) — actually click through the worker's real UI and try to break it, don't just API-test it.
