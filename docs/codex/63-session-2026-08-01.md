## What was built

### 1. alertFeed P0 Fix (CODEX 18)

**Root cause:** `authUser` was declared `let authUser = null` inside the `/chat:message`
handler's block scope (line 2802 in index.js). Four alertFeed routes at line 16100
referenced it outside that scope — JavaScript `let` is block-scoped, so every request
hit a ReferenceError that Firebase returned as a 404.

**Fix:** Each of the four alertFeed routes (`GET /alertFeed`, `POST /alertFeed:push`,
`POST /alertFeed:resolve`, `POST /alertFeed:snooze`) now calls `requireFirebaseUser`
inline, consistent with accounting and other auth-gated routes. The operating feed
is live in production.

Additional hardening:
- `alertFeed:resolve` is idempotent — returns `{ ok: true, alreadyResolved: true }` on
  second call instead of erroring
- `alertFeed:snooze` accepts either `snoozeHours` (1/4/24/72) or a `snoozedUntil`
  timestamp override for custom snooze windows
- `horizon` field on push is validated against the fixed enum
  `["today","this-week","next-week","waiting_external","snoozed","someday"]`
