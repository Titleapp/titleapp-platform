## Why this exists

Testing `/demo/title` led to testing `/demo/nursing`, which led to checking `/demo/education` — and it's broken. Sean's own words on what it was *supposed* to be: *"the education [demo] was really supposed to be an example of how a teacher can use our mini sandbox to create course workers, the evaluation workers help teachers teach, and the course workers help students learn through AI tutoring."*

That's a real, coherent product idea that was apparently never finished. This spec scopes rebuilding `/demo/education` to actually be that — not a cosmetic fix to the current broken routing.

## What already exists to build on

- **The generic worker-build sandbox already exists and is not education-specific.** `apps/business/src/pages/WorkerSandbox.jsx` (CODEX 47.4/48.5), 9-step flow, backend `functions/functions/services/sandbox/workerBuildFlow.js`. This *is* Sean's "mini sandbox" — it already works today. Whether a teacher uses this directly or the simpler upload-first front door (S52.55) is a separate question from whether the underlying capability exists — it does.
- **`nursing-education-001` (worker name "Hannah") is a fully-built, real, working example of exactly the Evaluation-Worker/Course-Worker pattern Sean described** — verified live on `/demo/nursing`, not assumed:
  - **Evaluation-worker side** (instructor view): a real cohort dashboard — 8 named students, per-student longitudinal timelines (attendance, reflections, SLO scores, professionalism ratings, incidents), grades that lock and get chain-anchored on Base (`0x4f2e...a1b3 ✓ on Base · Immutable`), and a pedagogically serious framing where a self-reported near-miss is explicitly counted as a *strength*, not a failure.
  - **Course-worker side** (student view, "Sarah K."): personalized growth feedback tied to her actual weakest SLO (delegation, 2.5/5), a reflection-writing flow, and an exportable "verified record" she carries herself. **Correction from an earlier draft**: this is not "FERPA-portable" — FERPA is the school's obligation about *its* records; what's actually happening is a student exporting *her own* data to show someone else, which is a different (and unnamed-in-code) legal footing, not a named regulation's compliance feature. Don't reuse "FERPA-portable" language until someone actually checks what FERPA requires here, if anything.
  - **AI tutoring, tested live**: asked Hannah, in the student's voice, "I'm struggling with delegation... can you help me understand when to delegate a task vs doing it myself?" — got back a specific, well-structured, pedagogically sound framework, not generic filler.
  - **Caveat, stated plainly**: this pair was hand-built by engineers, not actually built by "Dr. Kealani Moku" through the sandbox UI in the demo's own narrative. It's proof the *pattern* is good and worth generalizing — it is not evidence that a teacher today could reproduce it themselves without engineering help.

## What's missing — real gaps

- **No K-12/general-subject demo persona or content exists anywhere.** This is a from-scratch build, not a fix to something half-done.
- **No demo narrative walks anyone through actually building anything.** Neither the raw 9-step flow nor the S52.55 fast path has an education-flavored narrative built on top yet.
- **No child-privacy regime is named anywhere in this spec or the code it touches — and this got more urgent, not less, once the persona was confirmed as K-12 rather than "generic education."** COPPA (under-13 data collection), FERPA's actual minor-specific provisions (distinct from the export-framing issue above), and state student-data-privacy statutes (many states have their own, stricter than federal) are all real, applicable, and currently unaddressed. This matters concretely because S52.55's fast path has AI deriving rules directly from materials that will shape how a worker talks *to children* — that derivation step is exactly where a privacy-compliance gap would first show up (e.g., a course worker asking a student for information it shouldn't retain, or retaining chat transcripts in a way state law restricts for minors).
- **No K-12 pedagogical subject-matter expert is named**, unlike aviation and nursing, both of which have real named advisors on record in `functions/functions/raas/company-knowledge.md` — verified directly, not assumed: *"Eric Altshuler (Advisor — Terminal & Open Source): Naval aviator, FedEx 777 Captain"* and *"Ruthie Clearwater, PhD (Creator Community Lead): Nationally ranked nursing program faculty + EMS flight nurse... Authoring nursing education workers."* `nursing-education-context.md` confirms Dr. Clearwater actually authored the nursing worker's real courses, SLOs, reflection templates, and clinical sites — she isn't a demo-only fictional persona, she's the real content author on record. Building K-12 assessment/pedagogy content without an equivalent named, real expert reviewing it is the same gap-shaped hole nursing and aviation both avoided by having one.
- **No user-facing synthetic-data disclosure for the demo's own student personas — verified, not assumed.** `nursing-education-context.md` internally and correctly labels its 8 students as *"demo students"* (line 86) and instructs the AI worker not to invent beyond them — but that's guidance to the AI, not a disclosure shown to whoever's looking at the cohort dashboard. There's no equivalent of the title vertical's explicit `disclaimer: "SAMPLE — FOR DEMONSTRATION ONLY..."` field baked into what a viewer actually sees. If this K-12 demo invents named students the way nursing's cohort does, it needs that same explicit, user-facing labeling — more so for a demo involving fictional minors than for fictional property records.
- **The Evaluation Worker's dashboard UI (cohort/SLO/chain-anchor/reflection view) is currently nursing-specific** — built directly for nursing clinical rotations (SLOs numbered per nursing program standards, clinical site fields, instructor-signed grade locks). Generalizing it for "any teacher, any subject" needs the same kind of care given to Business Vault's generalization (S52.53) — identify what's genuinely generic (append-only event timeline, locked+anchored grades, self-report-as-strength framing) vs. what's nursing-specific before assuming it ports as-is.

## Proposed shape (for review, not yet built)

1. **Use S52.55's upload-first fast path as the demo's front door** — not the raw 9-step sandbox, not a pre-built landing page. The mechanism itself (upload → AI derives config → plain-language confirmation → Test protocol → publish) is scoped in S52.55; this demo's job is applying it to a real K-12 subject and narrative.
2. **Pick a real, concrete teacher persona and subject** — not "generic K-12," a specific one (e.g., a 5th-grade science teacher, or a high-school subject with clearer assessment rubrics) so the demo has the same specificity that makes the title/nursing demos land.
3. **Build two workers from that flow**: a **Course Worker** (subject-matter AI tutoring, generalizing the "personalized growth feedback tied to a real weak spot" pattern proven in nursing) and an **Evaluation Worker** (teacher-facing dashboard — generalizing the cohort/timeline/locked-grade pattern, with the nursing-specific fields swapped for whatever the chosen subject's real assessment structure is).
4. **Reuse, don't rebuild, the append-only chain-anchoring** — locked grades anchored on-chain and immutable even to the teacher generalizes cleanly and is worth keeping identical.
5. **Do NOT reuse nursing's "self-report as strength, not punishment" framing as-is for K-12** — see the mandatory-reporting open decision below. This needs a K-12-specific answer, not a copy-paste of the adult-nursing-student framing.
6. **Fix the routing bug regardless of scope decisions above**: `activeWorkers: ["nursing-education-001"]` at `index.js:1990` must not stay wired to a nursing persona under a K-12 principal identity even as an interim state.

## Open decisions needing Sean's sign-off

- **Mandatory-reporting / escalation path — a duty-of-care question, not a UI-porting question.** For adult nursing students, a self-reported near-miss escalating to an instructor is pedagogical, and nursing's framing ("counted as a strength") is well-suited to that. For K-12, a course worker having a conversation with a child may surface something a school has an actual **legal mandatory-reporting obligation** to act on — disclosure of self-harm, abuse, or neglect. Nursing's Test protocol already has an "escalation behavior" question (S52.55, red-team question #3: "what does the worker do when a subscriber is about to make a serious mistake?") — but that question is scoped to *pedagogical* mistakes, not child-safety disclosures. This needs its own answer: does a K-12 Course Worker need a hard-coded, non-negotiable escalation path to a real adult for specific disclosure categories, separate from and stricter than whatever RAAS rules the AI derives from uploaded materials? Recommend yes, but this is Sean's call given the legal exposure involved, not something to assume.
- **Child-privacy regime compliance** — needs actual legal/compliance input (COPPA, FERPA minor provisions, relevant state statutes), not an engineering guess. Flagging the gap here; not attempting to resolve it in this doc.
- **Named K-12 pedagogical SME** — same pattern as aviation/nursing. Needs a real name before real content gets built, not a placeholder.
- **Subject and grade level for the demo persona** — needs a specific pick, not "generic K-12," per point 2.
- **How much of nursing's Evaluation Worker UI generalizes vs. gets rebuilt** — recommend a quick audit (same discipline as S52.53's asset-class mapping fix) before assuming the cohort/SLO dashboard just needs relabeling.
- **Sequencing** — this doc now explicitly depends on S52.55 shipping (or at least being far enough along) before this demo's narrative can be built on top of it.
